# Kinwhim store launch kit

Everything needed to get Kinwhim into the App Store, then Google Play. Copy-ready listing text is in [app-store.md](app-store.md) and [google-play.md](google-play.md), privacy answers are in [privacy-disclosures.md](privacy-disclosures.md), and the screenshot plan is in [screenshots.md](screenshots.md). Store artwork is in [`artwork/`](artwork) and is regenerated by `npm run icons` in `mobile/`.

## 1. Decisions to make before launch

- [ ] **Hosting.** The API runs on Cloudflare Workers with D1 and R2. It works unchanged on the current ChatGPT Sites deployment *if* that deployment can be made public, serve `kinwhim.app`, and hold the secrets below. Otherwise, deploy the same worker to your own Cloudflare account. Universal links need `https://kinwhim.app/.well-known/apple-app-site-association` to be served from the real domain.
- [ ] **Remove the private tester allowlist.** This lives in the hosting settings, not in code. Make the site public; access is now controlled by Kinwhim sign-in plus invite-only circles.
- [ ] **Legal details.** Fill in `LEGAL_ENTITY`, `LEGAL_ADDRESS`, and `GOVERNING_LAW` in [`lib/policies.ts`](../../lib/policies.ts), and have counsel review `/privacy`, `/terms`, and `/safety`. They describe the actual behavior of the code, but they are drafts.
- [ ] **Mailboxes.** Create `support@`, `safety@`, and `privacy@kinwhim.app`, and make sure someone reads `safety@` every day. Both stores expect reports to be handled promptly; the published policy says within 24 hours.

## 2. Accounts and keys

| What | Where | Then set |
| --- | --- | --- |
| Apple Developer Program | developer.apple.com | Team ID |
| App ID `app.kinwhim` with Sign in with Apple, Push Notifications, Associated Domains | Certificates, IDs & Profiles | `APPLE_CLIENT_IDS=app.kinwhim`, `APPLE_APP_IDS=<TEAMID>.app.kinwhim` |
| Sign in with Apple key (.p8) | Keys | `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY` (needed to revoke tokens on account deletion) |
| APNs key | Keys, or let `eas credentials` create it | uploaded to EAS |
| Google OAuth clients: Web, iOS, Android | Google Cloud Console → Credentials | `GOOGLE_CLIENT_IDS` (all three) and the mobile `EXPO_PUBLIC_GOOGLE_*` values |
| Expo project | `npx eas-cli@latest init` in `mobile/` | `EAS_PROJECT_ID` |
| Resend domain `kinwhim.app` | resend.com | `RESEND_API_KEY`, `EMAIL_FROM` |
| Google Play Console | play.google.com/console | `ANDROID_CERT_SHA256` from Play App Signing |

Other server secrets: `OPENAI_API_KEY`, `PUBLIC_APP_URL=https://kinwhim.app`, `MODERATION_EMAIL=safety@kinwhim.app`, `ADMIN_TOKEN`, `CRON_SECRET`, `REVIEW_EMAIL`, `REVIEW_CODE`, `APP_STORE_URL`, `PLAY_STORE_URL`.

## 3. Backend go-live

- [ ] Apply `drizzle/0003_pink_raider.sql` to production D1. It adds the auth and safety tables, and backfills who appears in existing memories.
- [ ] Schedule `POST /api/cron/nightly` hourly with `Authorization: Bearer $CRON_SECRET`. It makes due memories, purges selfies older than 14 days, and clears expired sessions.
- [ ] Check that `https://kinwhim.app/.well-known/apple-app-site-association` lists `<TEAMID>.app.kinwhim` and that `/.well-known/assetlinks.json` lists the Play signing fingerprint.
- [ ] Existing testers: signing in with Apple, Google, or email using the **same verified email** as their ChatGPT account links to their existing circles and memories. With Apple “Hide My Email”, the address won’t match; they can sign in with email instead.

## 4. Moderation runbook

- Reports arrive by email (`MODERATION_EMAIL`). The queue is at `GET /api/admin/reports` with `Authorization: Bearer $ADMIN_TOKEN`.
- Review the evidence at `GET /api/admin/reports/<id>/evidence`.
- Act with `POST /api/admin/reports/<id>` and `{"action": "dismiss" | "remove_content" | "suspend_user" | "remove_and_suspend", "note": "…"}`. Suspending signs the person out everywhere and blocks future sign-ins.
- For apparent CSAM: don’t download or forward it. Use `remove_and_suspend`, then report to NCMEC CyberTipline (US) and preserve the evidence as the law requires.

## 5. App Store submission

- [ ] `npx eas-cli@latest build --profile production --platform ios`, then `eas submit`.
- [ ] Fill in the listing from [app-store.md](app-store.md) and App Privacy from [privacy-disclosures.md](privacy-disclosures.md).
- [ ] Age rating questionnaire: see [app-store.md](app-store.md#age-rating).
- [ ] App Review demo account: set `REVIEW_EMAIL`/`REVIEW_CODE` and put them in the review notes. Seed that account in a circle with a second demo account and at least one memory, so reviewers can see every feature.
- [ ] Screenshots per [screenshots.md](screenshots.md).

## 6. Google Play

- [ ] `npx eas-cli@latest build --profile production --platform android`, upload to the internal testing track, then closed testing. New personal developer accounts need 12+ testers for 14 days before production.
- [ ] Listing, content rating, Data safety, and the account-deletion URL from [google-play.md](google-play.md) and [privacy-disclosures.md](privacy-disclosures.md).
- [ ] Child Safety Standards (required for social apps): link `https://kinwhim.app/safety` and name `safety@kinwhim.app` as the contact.
- [ ] Test **Save to Photos** on Android 10–15 devices. The app deliberately declares no media-read permissions.

## Known gaps

- The web app supports email sign-in only. Apple and Google sign-in are in the mobile app.
- The web “mini movie” isn’t in the native app yet; native shares the still image.
- Report, block, and remove are built into the native app and API. The web UI has terms, account deletion, and selfie deletion, but not report/block buttons yet.
